# Dipankar Kumar — Personal Engineering Portfolio

> **Learn the problem needs, then build it.**

Personal portfolio of **Dipankar Kumar**, an MCA student at MANIT Bhopal focused on software engineering, application development, systems integration, data, and continuous technical learning.

The portfolio is designed to show **real work and engineering growth** rather than simply listing technologies.

---

## About the Project

This repository contains the source code for Dipankar's personal engineering portfolio.

The portfolio is intended to communicate:

- What Dipankar builds
- How he approaches technical problems
- What technologies he can currently work with
- What he is learning
- How his projects and capabilities are evolving

The site intentionally favors **clarity, authenticity, maintainability, and working functionality** over unnecessary visual or technical complexity.

---

## Design Direction

The visual direction is inspired by the selected **Picto-style portfolio reference**: clean layouts, strong typography, structured grids, generous whitespace, and restrained interactions.

The website is an engineering portfolio, not a design showcase.

> **The website should make the work memorable, not the website itself.**

---

## V1 Technology Stack

- **React**
- **TypeScript**
- **Vite**
- **CSS**
- **Structured local content/data**
- **Git / GitHub**
- **Vercel**

V1 intentionally has no backend, database, CMS, authentication system, or unnecessary animation framework.

---

## Running Locally

Clone the repository and install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Create a production build:

```bash
npm run build
```

Preview the production build locally:

```bash
npm run preview
```

## Engineering Philosophy

This portfolio follows the same principle it communicates:

> **Learn the problem needs, then build it.**

That means the project should:

- Choose technology according to the actual requirement.
- Avoid unnecessary complexity.
- Keep content and code maintainable.
- Represent skills and experience honestly.
- Prefer working software over superficial polish.
- Evolve as new projects and capabilities are developed.
